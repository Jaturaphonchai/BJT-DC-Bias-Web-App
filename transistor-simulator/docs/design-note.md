# Design Note — BJT DC Bias Web App

เอกสารสรุปการตัดสินใจออกแบบ (ฉบับเต็ม: `../../docs/superpowers/specs/2026-11-10-bjt-dc-bias-web-app-design.md`)

## ปัญหาที่แก้

นักศึกษาต้องเห็นว่าเว็บแอปจริงไม่ได้จบที่ HTML ไฟล์เดียว แต่มี HTTP request วิ่งไปถึง
Python backend ที่คำนวณ แล้วส่งผลกลับมาเป็น HTML

## ทางเลือกที่พิจารณา

| ทางเลือก | ข้อดี | ข้อเสีย | ผล |
|---|---|---|---|
| Server-rendered form + POST `/calculate` | ตรง acceptance, ไม่มี JS, test ง่าย | ต้องกด submit ทุกครั้ง | **เลือก** |
| JSON API + fetch | ต่อยอด interactive ได้ | โค้ดและ test เพิ่มเกือบเท่าตัว | ไม่เลือก |
| POST `/` route เดียว | สั้นที่สุด | แยกหน้าที่ไม่ชัด | ไม่เลือก |

## การตัดสินใจสำคัญ

1. **แยก `dc_bias.py` ออกจาก `app.py`** เพื่อให้สมการถูกทดสอบได้โดยไม่ต้องเปิดเว็บ
2. **รับค่าตัวต้านทานเป็น kΩ** เพราะค่าจริงในใบงานอยู่ในช่วง kΩ และลดการพิมพ์เลขศูนย์ผิด
3. **Validation อยู่ในโมดูลวิศวกรรม** ไม่ใช่ใน route เพื่อให้ unit test ครอบคลุมได้
4. **รายงาน Region เป็น 3 สถานะ** (active/cutoff/saturation) แทนการปล่อยให้ผู้ใช้ตีความเลขเอง
5. **Error แสดงรายช่องและคงค่าที่กรอก** เพื่อให้แก้ไขได้เร็ว
6. **ไม่ใช้ JavaScript** เพื่อให้เห็นเส้นทาง request → Python → template อย่างชัดเจน
7. **ใช้สมการเต็มที่คิด `IB` เท่านั้น** — ไม่แสดงวิธีประมาณที่ละ `IB` เพราะชุดค่าอ้างอิงให้
   `RTH = 18 kΩ` ซึ่งไม่เล็กกว่า `(β+1)·RE = 101 kΩ` มากนัก
   วิธีประมาณจึงคลาดเคลื่อนจากสมการจริงประมาณ 18%
